There are words the model does not know. A company name, a colleague's surname, an internal term, a project name. They are rare in ordinary speech, so the model substitutes something that sounds similar — and the text becomes almost right, but someone else's. “Petukhov” instead of “Petrov”, “FormaMind” instead of “FormaMind”, “continuum” mangled into “continium”.

In 0.5.0 a layer appeared that makes dictation yours: a dictionary, application profiles, punctuation languages, text cleanup and voice actions.

## A dictionary that reaches every window

Before, the dictionary reached only the first 30-second recognition window. After that the model worked without it — and a term named at the start was lost in the middle. Now `hotwords` are passed to every window: dictation, live hints, the sequential and batched file paths.

The budget is 223 tokens. Terms are selected by correction frequency and passed in their target form. A term that does not fit is skipped whole, never cut mid-word. Every window writes one log line with the number of terms — without the terms themselves.

## Application profiles

One dictionary for everything is a compromise. A chat needs people's names, an IDE needs function and library names, accounting needs codes and amounts. `app_profiles` binds a profile to a process name and/or a window-title fragment; a profile has its own dictionary and its own snippets.

The profile of the window that will receive the text is applied — the one active at the moment the hotkey is pressed, not the one active when recognition ends. Profile rules are layered over global ones without duplicates; other windows keep living with the global set. The limit is 50 profiles.

In settings, on the Dictionary tab, there is an “Application profiles” section: list, add, edit, delete, profile terms and snippets, save and reset.

## 26 punctuation languages

Punctuation presets used to cover six languages. Now they cover all 26 menu languages, each in its own script and alphabet. The model gets a hint about how to punctuate, not only about which words to expect.

## Text cleanup

`text_cleanup` (off by default, no separate settings tab yet) turns spoken numbers and dates into digits for Russian and English through `wetext` 0.2.1. It removes a curated list of filler words as whole words and capitalizes sentence starts.

Protected fragments stay byte for byte: code, snake_case and camelCase, dotted paths, URLs, e-mails, Windows paths and text in backticks. Cleanup runs after the dictionary, rules, snippets and voice actions, before the draft and insertion. Punctuation stays with Whisper.

## Snippets and voice actions

Snippets substitute frequently used phrases on a short trigger. Voice actions (`actions` in `config.json`) are a whole spoken phrase that matched after the dictionary and snippets: it runs `hook_command`, switches the model or starts a command for an external agent. A matched action is not inserted as text; a failed command leaves the ordinary insertion and writes a status line to the log.

There is also `dictation_context` (off by default): the previous phrase (a 160-character tail) and the text selected in the target window (up to 400 characters) go into `hotwords` so a name keeps its spelling. With the option off, nothing is read.

## Models: own folders and updates by consent

0.5.1 added local model folders: `model` accepts a path to a CT2 folder, validated structurally — `model.bin` with a CT2 header, `config.json` as an object, `tokenizer.json` and a vocabulary. A broken folder gives a named error instead of quietly downloading a catalog model.

0.5.5 added model updates by consent: a background check every 24 hours compares downloaded models with Hugging Face and offers a new revision with “Update” and “Not now” buttons. An update runs only on a click, one model at a time, only when idle. The previous revision is kept as `previous-<model>-<revision>` so you can roll back without downloading again.

## Where the border is

`text_cleanup` is still config-only: there is no separate settings tab. A lone small number outside a recognized phrase stays as words — that is a `wetext` rule. Profiles layer without duplicates but do not replace global rules. Model updates need a network and a click; offline dictation does not depend on them.

And the main thing: personalization is a layer, not a replacement for recognition. If the model does not hear a word, the dictionary helps; if the sound is bad, no dictionary will.
