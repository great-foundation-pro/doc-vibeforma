Все файлы VibeForma лежат в каталоге установки. По умолчанию это `%LOCALAPPDATA%\VibeForma`; `-Target` может его перенести.

## Структура

| Путь | Что это | Формат |
|---|---|---|
| `config.json` | Настройки, словарь, сниппеты, hotwords, модель, язык, токен API | JSON |
| `models\<имя>\` | Модель распознавания | Файлы модели |
| `logs\` | Ротируемые логи | Текст |
| `history.jsonl` | Последние 100 диктовок, когда история включена | JSON Lines |
| `stats.json` | Счётчики по дням | JSON |
| `corrections.json` | Слова, изменённые обучением из правок | JSON |
| `location.json` | Файл обнаружения для локальных инструментов | JSON |
| `status.json` | Текущее состояние сервиса | JSON |
| `service.lock` | Блокировка одного экземпляра | Файл блокировки |
| `install.log` | Шаги установщика и обновлятора | Текст |
| `test_ru.wav` | Тестовая фраза для `--selftest` | WAV |
| `.venv\` | Виртуальное окружение Python | Каталог |
| `main.py`, `run.cmd` | Точки входа приложения | Python / batch |
| `uninstall.cmd`, `uninstall.py` | Удалятор | Batch / Python |

## config.json

Единый файл конфигурации. В нём:

- настройки записи, вида и системы;
- словарь и сниппеты;
- `hotwords`;
- выбранная модель и язык;
- переключатель, порт и токен локального API;
- `onboarding_done`.

Файл пишется атомарно через временный файл и `os.replace`, поэтому сбой не оставляет сломанную конфигурацию.

Токен API — секрет. Не вставляйте `config.json` в issue; вырезайте токен.

## Модели

`models\<имя>` внутри папки сервиса — первое место, где VibeForma ищет модель. Если её нет, пробуется общий кэш Hugging Face, затем свежая загрузка.

Удаление папки модели вызовет загрузку при следующем выборе этой модели.

## Логи

`logs\` хранит пять файлов по 1 МБ с ротацией. Продиктованный текст в лог не пишется. Заголовки окон пишутся только при `log_window_titles: true`; по умолчанию в логе только хэндл окна и число знаков.

В трее есть пункт **Папка логов**, который открывает каталог.

## История и статистика

| Файл | Содержит | Удаление |
|---|---|---|
| `history.jsonl` | Текст, число знаков, приложение, направление, время | Убирает историю; диктовка продолжает работать |
| `stats.json` | Четыре счётчика за день | Сбрасывает статистику; история не затрагивается |

История выключена по умолчанию, а её выключение удаляет файл. Статистика хранит только числа.

## location.json

Публикуется сервисом, чтобы локальные инструменты находили его без догадок:

| Поле | Значение |
|---|---|
| `schema` | Версия схемы файла |
| `app` | Имя приложения |
| `version` | Версия продукта |
| `config` | Путь к конфигурации |
| `api` | `on`, `off` или `error` |
| `port` | Фактический порт, который слушает API |

Секрета в этом файле нет. Токен остаётся в `config.json`.

## status.json

Пишется на каждом изменении состояния. В нём состояние, версия, pid и метка времени. Это удобство для скриптов, а не источник истины; ответ старше 60 секунд не считается достоверным.

## service.lock

Блокировка одного экземпляра. Она не даёт второму сервису стартовать и драться за микрофон, горячую клавишу и порт API.

## install.log

Установщик и обновлятор пишут сюда каждый шаг и хвост ошибки. Это первый файл, который надо читать, если установка или обновление не удались.

## Временные файлы

`POST /transcribe` пишет временный WAV с именем `_http_in_*.wav` и удаляет его при любом исходе. Аудио после распознавания не хранится.

## Резервная копия и удаление

- **Копируйте** `config.json`, `models\` и — если нужны — `history.jsonl`, `stats.json`, `corrections.json`.
- **Удаление** убирает ярлыки, автозапуск и файлы сервиса; модели и `config.json` остаются без `--remove-data`.
- **Чистый сброс** — переустановка с `--remove-data` или удаление каталога установки после удаления приложения.
