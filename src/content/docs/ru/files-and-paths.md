Почти все файлы VibeForma лежат в каталоге установки. По умолчанию это `%LOCALAPPDATA%\VibeForma`; `-Target` может его перенести. Исключение — записи системного звука: по умолчанию они пишутся в вашу папку «Документы».

## Структура

| Путь | Что это | Формат |
|---|---|---|
| `config.json` | Настройки, словарь, сниппеты, hotwords, модель, язык, токен API | JSON |
| `models\<имя>\` | Модель распознавания | Файлы модели |
| `logs\` | Ротируемые логи | Текст |
| `history.jsonl` | Последние 100 диктовок, когда история включена | JSON Lines |
| `stats.json` | Счётчики по дням | JSON |
| `corrections.json` | Слова, изменённые обучением из правок | JSON |
| `location.json` | Файл обнаружения для локальных инструментов | JSON |
| `status.json` | Текущее состояние сервиса | JSON |
| `service.lock` | Блокировка одного экземпляра | Файл блокировки |
| `install.log` | Шаги установщика и обновлятора | Текст |
| `test_ru.wav` | Тестовая фраза для `--selftest` | WAV |
| `.venv\` | Виртуальное окружение Python | Каталог |
| `main.py`, `run.cmd` | Точки входа приложения | Python / batch |
| `uninstall.cmd`, `uninstall.py` | Удалятор | Batch / Python |

## config.json

Единый файл конфигурации. В нём:

- настройки записи, вида и системы;
- словарь и сниппеты;
- `hotwords`;
- выбранная модель и язык;
- переключатель, порт и токен локального API;
- лимиты и корни файлового режима;
- `onboarding_done`.

Файл пишется атомарно через временный файл и `os.replace`, поэтому сбой не оставляет сломанную конфигурацию.

Токен API — секрет. Не вставляйте `config.json` в issue; вырезайте токен.

## Модели

`models\<имя>` внутри папки сервиса — первое место, где VibeForma ищет модель. Если её нет, пробуется общий кэш Hugging Face, затем свежая загрузка.

Удаление папки модели вызовет загрузку при следующем выборе этой модели.

Папка, добавленная в локальный список в **«Настройки → Модель и язык»**, — ваш файл, где бы она ни лежала: смена модели её не удаляет, `model_keep_old: false` убирает только скачанные модели внутри `models\`, а полное удаление приложения её не трогает.

## Логи

`logs\` хранит пять файлов по 1 МБ с ротацией. Продиктованный текст в лог не пишется. Заголовки окон пишутся только при `log_window_titles: true`; по умолчанию в логе только хэндл окна и число знаков.

В трее есть пункт **Папка логов**, который открывает каталог.

## История и статистика

| Файл | Содержит | Удаление |
|---|---|---|
| `history.jsonl` | Текст, число знаков, приложение, направление, время | Убирает историю; диктовка продолжает работать |
| `stats.json` | Четыре счётчика за день | Сбрасывает статистику; история не затрагивается |

История выключена по умолчанию, а её выключение удаляет файл. Статистика хранит только числа.

## location.json

Публикуется сервисом, чтобы локальные инструменты находили его без догадок:

| Поле | Значение |
|---|---|
| `schema` | Версия схемы файла; `2` добавляет поля файлового режима |
| `app` | Имя приложения (`vibeforma`) |
| `version` | Версия продукта |
| `launcher`, `python`, `entry` | Три способа запустить приложение |
| `install_dir`, `config`, `app_dir` | Пути, которые могут понадобиться локальному инструменту |
| `pid`, `updated` | Процесс, записавший файл, и метка времени Unix |
| `file_mode` | `true`, когда именованный канал слушает; `false`, пока идёт загрузка |
| `formats`, `languages` | Что принимает запущенная сборка |
| `max_file_mb`, `max_file_s`, `max_sync_s` | Действующие лимиты |
| `pipe` | Только когда канал слушает |
| `api` | `on`, `off` или `error` |
| `port` | Фактический порт, который слушает API |

Секрета в этом файле нет. Токен остаётся в `config.json`.

## Результаты транскрибации файлов

Расшифровка по умолчанию пишется рядом с исходником, с его именем и расширением формата (`meeting.mp4` → `meeting.srt`). `--out` называет другой файл или папку; для пакета папки дерево зеркалится под указанным местом. Существующий результат пропускается, если не передан `--force`.

TXT, JSON, SRT и VTT описаны на странице [«Форматы расшифровки»](/ru/formats/). API отвечает телом ответа и файлов не пишет.

## Записи системного звука

Запись с источником звука **«Системный звук»** пишется в файлы, и эти файлы не относятся к установке:

| Путь | Что это | Формат |
|---|---|---|
| `<system_recordings_dir>\<дата>\<ЧЧ-ММ-СС>.wav` | Звук записи, 16 бит, 16 кГц моно | WAV |
| То же имя с `.txt` | Расшифровка, поставленная в очередь по остановке | Текст |
| То же имя с `.srt` | Та же расшифровка как субтитры | SRT |

`system_recordings_dir` по умолчанию пуст, то есть означает `Documents\VibeForma\Recordings` — папку «Документы» Windows, которую перенаправленный или OneDrive-профиль переносит вместе с остальными вашими документами. Папка задаётся в **Настройках → Запись**: поле показывает действующий путь, **«Изменить…»** выбирает другую папку, **«По умолчанию»** возвращает умолчание; пустой ключ следует за папкой «Документы». Подпапка даты создаётся на каждый день, а файл назван временем начала записи; вторая запись в ту же секунду получает числовой суффикс вместо перезаписи. Недоступная папка сообщается до старта записи.

WAV, TXT и SRT — ваши файлы: полное удаление приложения оставляет их на месте, как и любую расшифровку, сделанную файловым заданием.

## status.json

Пишется на каждом изменении состояния. В нём состояние, версия, pid и метка времени. Это удобство для скриптов, а не источник истины; ответ старше 60 секунд не считается достоверным.

## service.lock

Блокировка одного экземпляра. Она не даёт второму сервису стартовать и драться за микрофон, горячую клавишу и порт API.

## install.log

Установщик и обновлятор пишут сюда каждый шаг и хвост ошибки. Это первый файл, который надо читать, если установка или обновление не удались.

## Временные файлы

`POST /transcribe` пишет временный WAV с именем `_http_in_*.wav` и удаляет его при любом исходе. `POST /v1/audio/transcriptions` и `POST /jobs` используют файлы `_file_in_*` и `_file_job_*` в папке логов для загруженного тела и удаляют их после завершения. Аудио после распознавания не хранится.

## Резервная копия и удаление

- **Копируйте** `config.json`, `models\` и — если нужны — `history.jsonl`, `stats.json`, `corrections.json`. Расшифровки — обычные файлы рядом с исходниками; копируйте их вместе с этими папками. Записи системного звука лежат в папке записей и копируются как любой другой документ.
- **Удаление** из трея или через `uninstall.cmd` убирает ярлыки, автозапуск и запись в **Приложениях**. `--keep-data` сохраняет модели, конфигурацию, логи, историю, статистику и правки; `--remove-data` удаляет и их.
- **Полное удаление — это `uninstall.cmd --remove-data`.** Он убирает всё, что создали установщик и приложение, — пакет `vibeforma\`, `mcp.cmd`, файлы требований, историю и её звук, статистику, `status.json`, `location.json`, правки, верхнеуровневые `.py` и `.venv`, — и оставляет папку готовой к чистой установке. Файл, который принадлежит не приложению, остаётся и называется на экране. Записи системного звука, расшифровки и добавленные вами папки моделей — ваши файлы вне папки установки, они тоже остаются. Если `-Target` поставил приложение в другое место, `%LOCALAPPDATA%\VibeForma\location.json` лежит вне папки и перезапишется при следующем запуске.
- **Чистый сброс** — удалить папку и поставить приложение заново в то же место: отсутствующая или пустая папка для установщика — чистая установка. Полная процедура — на странице [Установка](/ru/installation/).
