У установленной копии есть небольшая командная строка. Она говорит с работающим сервисом, а не запускает второй.

## Точки входа

| Вход | Использование |
|---|---|
| `run.cmd` | Самый короткий путь; запускает приложение через встроенное виртуальное окружение |
| `.venv\Scripts\python.exe main.py` | Явная точка входа Python |

Старый README упоминает `VibeForma.exe`. Отдельного исполняемого файла в 0.2.4 нет: установленная копия — это копия исходников с `run.cmd`, `main.py` и `.venv`. Используйте один из двух входов выше.

Примеры ниже используют `run.cmd`.

## Флаги

| Флаг | Что делает |
|---|---|
| `--toggle` | Начинает или останавливает запись. |
| `--cancel` | Отбрасывает запись или черновик панели. |
| `--status` | Печатает `status.json` работающего экземпляра: state, version, pid, ts. |
| `--doctor` | Выполняет диагностические проверки и печатает `OK` / `WARN` / `FAIL` по строке. |
| `--selftest` | Выполняет импорты, загружает модель, распознаёт `test_ru.wav` и печатает текст. |

### `--toggle`

```powershell
.\run.cmd --toggle
```

То же, что нажатие горячей клавиши диктовки: начало или остановка записи.

### `--cancel`

```powershell
.\run.cmd --cancel
```

Отбрасывает фразу или черновик панели. Ничего не вставляется.

### `--status`

```powershell
.\run.cmd --status
```

Печатает состояние работающего экземпляра:

| Поле | Значение |
|---|---|
| `state` | idle, recording, processing, paused, updating, error |
| `version` | Версия продукта |
| `pid` | Идентификатор процесса |
| `ts` | Метка времени |

Ответ старше 60 секунд не считается текущим. `status.json` — удобство, а не источник истины.

### `--doctor`

```powershell
.\run.cmd --doctor
```

Проверяет Python, зависимости, модель на диске, профиль CUDA/CPU, микрофон, горячую клавишу, настройки обновления, свободное место и переключатели приватности. Каждая строка — `OK`, `WARN` или `FAIL`; код возврата 0, если провалов нет, и 1 иначе.

Отчёт только читает. В нём нет продиктованного текста, заголовков окон, hotwords, словаря, истории и HTTP-токена. В окне настроек есть кнопка **Скопировать отчёт** для того же вывода.

### `--selftest`

```powershell
.\run.cmd --selftest
```

Выполняет фиксированную цепочку: импорты → модель → `test_ru.wav` → распознанный текст. Код 0 — цепочка прошла, 1 — нет. WAV есть и в свежем git-клоне, и в установленной копии.

Это самый быстрый способ доказать, что распознавание на машине работает, независимо от микрофона.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | Успех — команда выполнена или проверки прошли. |
| 1 | Нет работающего экземпляра, провал проверки, провал selftest или неверная команда. |

`--toggle`, `--cancel` и `--status` требуют работающего сервиса. Без него они возвращают 1.

## Команда хука

`hook_command` отправляет распознанный текст вашей команде:

- текст приходит на **stdin** в UTF-8;
- команда запускается **без shell**, поэтому метасимволы — обычные символы;
- таймаут 1–30 секунд (`hook_timeout_s`);
- сбой или таймаут пишется в лог только как статус;
- вставка не затрагивается; хук работает параллельно.

Пример: небольшой Python-скрипт, который дописывает текст в заметку дня.

```powershell
.\run.cmd --status
```

Затем задайте `hook_command` в `config.json`, например:

```json
"hook_command": "python C:\\tools\\vibe-hook.py",
"hook_timeout_s": 5
```

Поскольку shell нет, не полагайтесь на `|`, `>`, `&&` или раскрытие переменных внутри строки команды. Логику кладите в скрипт.

## Рецепты для скриптов

Начать диктовку со Stream Deck или из скрипта:

```powershell
.\run.cmd --toggle
```

Проверить, свободен ли сервис, перед отправкой работы:

```powershell
.\run.cmd --status
```

Проверить свежую установку без микрофона:

```powershell
.\run.cmd --selftest
```

Собрать отчёт для поддержки:

```powershell
.\run.cmd --doctor > doctor.txt
```
