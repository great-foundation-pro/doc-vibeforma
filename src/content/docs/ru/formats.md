Расшифровку файла можно записать в четырёх форматах. Результат распознавания один и тот же; формат решает, сколько структуры идёт вместе с текстом.

| Формат | Для чего | Таймкоды |
|---|---|---|
| `txt` | Читать, вставлять в заметки | Нет |
| `json` | Скрипты, агенты, дальнейшая обработка | Да, на сегмент |
| `srt` | Субтитры в плеерах и редакторах | Да, на реплику |
| `vtt` | Веб-плееры и веб-страницы | Да, на реплику |

Командная строка по умолчанию пишет `srt`; `--format txt`, `--format json`, `--format vtt` или `--format all` выбирают другой, а `all` пишет все четыре файла. API называет формат в `response_format`.

## Кодировка и переводы строк

Каждый файл — UTF-8 без BOM, с переводами строк LF. Перенос, который принадлежит распознанной фразе, остаётся внутри своей реплики и не начинает новый нумерованный блок.

Таймкоды прижимаются к нулю и остаются монотонными. Пустые сегменты отбрасываются. Начало, конец и длительность округляются до миллисекунд.

## TXT

Чистый текст: один абзац на сегмент, пустая строка между абзацами и завершающий перевод строки. Таймкодов и метаданных нет.

```text
Доброе утро. Сегодня разбираем релиз.

Файловый режим готов, и панель показывает прогресс.
```

## JSON

Машиночитаемый объект с полным текстом, фактами о запуске и сегментами:

```json
{
  "text": "Доброе утро. Сегодня разбираем релиз.",
  "language": "ru",
  "model": "large-v3-turbo",
  "duration": 660.0,
  "segments": [
    {
      "start": 0.0,
      "end": 4.32,
      "text": "Доброе утро."
    },
    {
      "start": 4.32,
      "end": 9.15,
      "text": "Сегодня разбираем релиз."
    }
  ]
}
```

| Поле | Значение |
|---|---|
| `text` | Тексты всех сегментов, соединённые пробелами |
| `language` | Язык распознавания, когда известен |
| `model` | Модель, создавшая расшифровку |
| `duration` | Длительность источника в секундах |
| `segments` | Реплики с `start`, `end` и `text` |
| `segments[].words` | Необязательные пословные таймкоды, когда включён `file_word_timestamps` |

Пословные таймкоды используют ту же форму `start`/`end`/`text` внутри сегмента. По умолчанию они выключены: для большинства задач хватает таймкодов сегментов.

## SRT

SubRip: номер реплики, строка таймкода с запятой перед миллисекундами, текст и пустая строка перед следующей репликой.

```text
1
00:00:00,000 --> 00:00:04,320
Доброе утро.

2
00:00:04,320 --> 00:00:09,150
Сегодня разбираем релиз.
```

## VTT

WebVTT: заголовок `WEBVTT`, затем реплики с точкой перед миллисекундами. Номера реплик необязательны, и VibeForma их не пишет.

```text
WEBVTT

00:00:00.000 --> 00:00:04.320
Доброе утро.

00:00:04.320 --> 00:00:09.150
Сегодня разбираем релиз.
```

## Где выбирается формат

| Поверхность | Как выбирается формат |
|---|---|
| CLI одного файла | `--format txt\|json\|srt\|vtt\|all`; по умолчанию `srt` |
| CLI папки | Тот же `--format` применяется к каждому файлу пакета |
| `POST /v1/audio/transcriptions` | `response_format`: `json`, `text`, `srt`, `vtt` или `verbose_json` |
| `GET /jobs/<id>/result` | `?format=txt\|json\|srt\|vtt`; по умолчанию `txt` |

`verbose_json` возвращает полный JSON-объект выше; обычный `json` — только `{"text": "..."}`. API отвечает телом ответа и файлов не пишет. CLI пишет файлы рядом с исходником, если `--out` не указывает другое место, и не перезаписывает без `--force`.

## Чего в форматах нет

- Метки говорящих и оценки уверенности не пишутся.
- Нет стилей, позиционирования и караоке-тайминга внутри реплики.
- Перевода в расшифровке нет: текст на языке распознавания.
- Пословные таймкоды есть только в JSON.
