Расшифровку файла можно записать в четырёх форматах. Результат распознавания один и тот же; формат решает, сколько структуры идёт вместе с текстом.

| Формат | Для чего | Таймкоды |
|---|---|---|
| `txt` | Читать, вставлять в заметки | Нет |
| `json` | Скрипты, агенты, дальнейшая обработка | Да, на сегмент и на слово |
| `srt` | Субтитры в плеерах и редакторах | Да, на реплику |
| `vtt` | Веб-плееры и веб-страницы | Да, на реплику |

Командная строка по умолчанию пишет `srt`; `--format txt`, `--format json`, `--format vtt` или `--format all` выбирают другой, а `all` пишет все четыре файла. API называет формат в `response_format`.

## Кодировка и переводы строк

Каждый файл — UTF-8 без BOM, с переводами строк LF. Перенос, который принадлежит распознанной фразе, остаётся внутри своей реплики и не начинает новый нумерованный блок.

Таймкоды прижимаются к нулю и остаются монотонными. Пустые сегменты отбрасываются. Начало, конец и длительность округляются до миллисекунд.

## TXT

Чистый текст: один абзац на сегмент, пустая строка между абзацами и завершающий перевод строки. Таймкодов и метаданных нет.

```text
Доброе утро. Сегодня разбираем релиз.

Файловый режим готов, и панель показывает прогресс.
```

## JSON

Машиночитаемый объект с полным текстом, фактами о запуске и сегментами:

```json
{
  "text": "Доброе утро. Сегодня разбираем релиз.",
  "language": "ru",
  "model": "large-v3-turbo",
  "duration": 660.0,
  "segments": [
    {
      "start": 0.0,
      "end": 4.32,
      "text": "Доброе утро.",
      "avg_logprob": -0.21,
      "compression_ratio": 1.24,
      "no_speech_prob": 0.01,
      "temperature": 0.0,
      "words": [
        {"start": 0.0, "end": 0.42, "text": "Доброе", "probability": 0.98},
        {"start": 0.42, "end": 1.1, "text": "утро.", "probability": 0.95}
      ]
    },
    {
      "start": 4.32,
      "end": 9.15,
      "text": "Сегодня разбираем релиз."
    }
  ],
  "words": [
    {"word": "Доброе", "start": 0.0, "end": 0.42, "probability": 0.98},
    {"word": "утро.", "start": 0.42, "end": 1.1, "probability": 0.95}
  ]
}
```

| Поле | Значение |
|---|---|
| `text` | Тексты всех сегментов, соединённые пробелами |
| `language` | Язык распознавания, когда известен |
| `model` | Модель, создавшая расшифровку |
| `duration` | Длительность источника в секундах |
| `segments` | Реплики с `start`, `end` и `text` |
| `segments[].avg_logprob`, `compression_ratio`, `no_speech_prob`, `temperature` | Чтения уверенности движка для сегмента, округлённые до четырёх знаков; каждое присутствует, только если движок его вернул |
| `segments[].words` | Необязательные пословные таймкоды с `start`, `end`, `text` и `probability` |
| `words` | Массив верхнего уровня со всеми словами файла: `word`, `start`, `end` и `probability` |

Пословные таймкоды появляются при включённом `file_word_timestamps`, при запросе `word_timestamps` у задания или с флагом CLI `--words`. Движок также даёт вероятности слов для подсветки сомнительных слов в панели; JSON публикует их для клиентов.

Чтения — сырые значения движка, а не проценты. `temperature` выше нуля означает, что первый проход провалил проверку и сработал откат; `avg_logprob`, `no_speech_prob` и `compression_ratio` — проверки, на которых стоит защита от галлюцинаций. Чтения нет, когда движок его не вернул, поэтому клиент должен терпеть отсутствующие ключи.

## SRT

SubRip: номер реплики, строка таймкода с запятой перед миллисекундами, текст и пустая строка перед следующей репликой.

```text
1
00:00:00,000 --> 00:00:04,320
Доброе утро.

2
00:00:04,320 --> 00:00:09,150
Сегодня разбираем релиз.
```

## VTT

WebVTT: заголовок `WEBVTT`, затем реплики с точкой перед миллисекундами. Номера реплик необязательны, и VibeForma их не пишет.

```text
WEBVTT

00:00:00.000 --> 00:00:04.320
Доброе утро.

00:00:04.320 --> 00:00:09.150
Сегодня разбираем релиз.
```

## Как режутся реплики SRT и VTT

Когда пословные таймкоды доступны, реплика следует за предложением, а не за окном движка. Конец предложения (`. ! ? …`, с закрывающей кавычкой или скобкой после него) или пауза 0,6 секунды закрывают реплику. Слова из соседних окон движка и 600-секундных блоков склеиваются, если пауза короче, поэтому предложение не разрывается на шве движка. Реплика идёт от первого слова до последнего, а её начало прижимается к концу предыдущей реплики.

Без пословных таймкодов остаются сегменты движка: одна реплика на окно, как раньше. Готовый результат в обоих случаях прижимается к нулю и остаётся монотонным.

## Где выбирается формат

| Поверхность | Как выбирается формат |
|---|---|
| CLI одного файла | `--format txt\|json\|srt\|vtt\|all`; по умолчанию `srt` |
| CLI папки | Тот же `--format` применяется к каждому файлу пакета |
| `POST /v1/audio/transcriptions` | `response_format`: `json`, `text`, `srt`, `vtt` или `verbose_json` |
| `GET /jobs/<id>/result` | `?format=txt\|json\|srt\|vtt`; по умолчанию `txt` |

`verbose_json` возвращает полный JSON-объект выше, включая чтения уверенности и массив `words` верхнего уровня; обычный `json` — только `{"text": "..."}`. API отвечает телом ответа и файлов не пишет. CLI пишет файлы рядом с исходником, если `--out` не указывает другое место, и не перезаписывает без `--force`.

## Чего в форматах нет

- Метки говорящих не пишутся. Уверенность пишется в JSON — чтения сегментов и вероятности слов, — но не оформляется в субтитрах.
- Нет стилей, позиционирования и караоке-тайминга внутри реплики.
- Перевода в расшифровке нет: текст на языке распознавания.
- Пословные таймкоды пишутся только в JSON; SRT и VTT используют их для резки по предложениям, но не несут пословных меток.
