У VibeForma две диагностические команды, структурированный каталог ошибок и ротируемые логи. Вместе они отвечают на вопрос «может ли эта машина диктовать?» без догадок.

## `--doctor`

Запустить можно тремя способами:

```powershell
.\run.cmd --doctor
```

- из трея: **Диагностика**;
- из настроек: **Система → Диагностика**.

### Что проверяется

| Проверка | Что означает провал |
|---|---|
| Python | Интерпретатор отсутствует или вне поддерживаемого диапазона. |
| Зависимости | Нужный пакет отсутствует или сломан. |
| Модель на диске | Выбранной модели нет; диктовка упадёт или начнёт загрузку. |
| Профиль CUDA / CPU | Ожидалась CUDA, но она недоступна; нужен профиль CPU. |
| Микрофон | Нет устройства ввода или устройство не открывается. |
| Горячая клавиша | Сочетание не регистрируется — обычно им владеет другое приложение. |
| Настройки обновления | Конфигурация обновления противоречива. |
| Место на диске | Не хватает места под модель или обновление. |
| Переключатели приватности | Настройка приватности в неожиданном состоянии. |

Каждая строка — `OK`, `WARN` или `FAIL`. Код возврата 0, если провалов нет, и 1 иначе. Предупреждение — факт, который стоит знать, но не всегда блокер.

### Что содержит отчёт

Отчёт только читает. В нём нет:

- продиктованного текста;
- заголовков окон;
- `hotwords`;
- записей словаря;
- записей истории;
- HTTP-токена.

В окне настроек есть кнопка **Скопировать отчёт** для того же вывода. Отчёт можно безопасно приложить к issue, но прочитайте его один раз перед публикацией.

## `--selftest`

```powershell
.\run.cmd --selftest
```

Цепочка фиксирована:

1. импорты;
2. загрузка модели;
3. чтение `test_ru.wav`;
4. распознавание и печать текста.

Код 0 — цепочка прошла; 1 — нет. `test_ru.wav` есть и в свежем git-клоне, и в установленной копии.

Это самое быстрое доказательство, что распознавание на машине работает, независимо от микрофона и горячей клавиши. Если `--selftest` проходит, а диктовка нет — проблема в захвате, клавише или вставке, а не в модели.

## Каталог ошибок

У каждой ошибки, которую видит пользователь, есть:

- код;
- понятное сообщение;
- следующее действие.

Сообщения локализованы. Сырой текст исключения идёт только в лог, никогда в интерфейс. Когда сообщаете об ошибке, укажите код: он определяет ветку без скриншота.

## Логи

| Пункт | Деталь |
|---|---|
| Папка | `logs\` в каталоге установки |
| Ротация | Пять файлов по 1 МБ |
| Продиктованный текст | Никогда не пишется |
| Заголовки окон | Только при `log_window_titles: true`; по умолчанию лишь хэндл и число знаков |
| Открыть из приложения | Трей → **Папка логов** |

Типичная строка фиксирует смену состояния, вставку с числом знаков или сбой с кодом.

## `status.json`

Сервис пишет `status.json` на каждом изменении состояния:

| Поле | Значение |
|---|---|
| `state` | idle, recording, processing, paused, updating, error |
| `version` | Версия продукта |
| `pid` | Идентификатор процесса |
| `timestamp` | Когда состояние записано |

Это удобство для скриптов, а не источник истины. Ответ старше 60 секунд не считается достоверным.

## Что приложить к отчёту

1. Отчёт `--doctor`.
2. Последнюю часть текущего лога — с момента, когда началась проблема.
3. Код ошибки из интерфейса, если он был.
4. Шаги, которые воспроизводят проблему.
5. Версию Windows и наличие видеокарты NVIDIA.

Перед публикацией вырежьте токен API и личный текст. Отчёт доктора и так исключает и то, и другое.

## Если приложение вообще не стартует

1. Запустите `run.cmd --doctor` в терминале и прочитайте первый `FAIL`.
2. Прочитайте `install.log` в каталоге установки.
3. Запустите `--selftest`, чтобы отделить проблему модели от проблемы запуска.
4. Переустановите тем же установщиком; он продолжит с места сбоя.

Подробнее — в разделе [Решение проблем](/ru/troubleshooting/).
